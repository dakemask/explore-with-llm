## DeepSeek decisions
Sources: https://api-docs.deepseek.com/api/create-chat-completion, https://api-docs.deepseek.com/guides/thinking_mode/, https://api-docs.deepseek.com/quick_start/pricing, https://api-docs.deepseek.com/updates/
- **IDs.** The ID for V4.1 Flash is `deepseek-flash`, released 2026-09-10. The old name `deepseek-v4-flash` is "temporarily routed" to it. The Pro ID is `deepseek-v4-pro`.
- **Context and output.** Both models have a 1M context and a maximum output of 384K. Flash supports vision; Pro does not.
- **Thinking switch.** Thinking is set with `thinking: {type: enabled|disabled}`, and the default is enabled. The `思考` choice uses `enabled` / `disabled` and defaults to `enabled`.
- **Thinking effort.** `reasoning_effort` accepts `low` / `high` / `max`, and the default is `high`. The API also maps legacy values (minimal→low, medium/xhigh→high) and accepts `none`. `思考强度` offers only `low` / `high` / `max`, requires `思考 = enabled`, and defaults to `high`.
- **max_tokens.** The default is 8K when thinking is off, 64K with thinking, and 128K at `max` effort. `最大输出` is a toggle that starts off, so the API defaults apply. The range is 1000–384000.
- **temperature.** It is ignored in thinking mode (no error), and its range is 0–2. `温度` requires `思考 = disabled`.
- **top_p.** It only takes effect in thinking mode, and only between 0.95 and 1, so I didn't expose it.
- **Usage in streams.** I send `stream_options.include_usage` as a silent item.
- **Echo: off.** The docs say that without tools, `reasoning_content` "does not need to be passed back; even if passed to the API, it will be ignored".

## OpenAI decisions
Sources:
- Model pages, e.g. https://developers.openai.com/api/docs/models/gpt-6-astra
- https://developers.openai.com/api/docs/guides/latest-model and its `?model=gpt-5.6` page
- https://developers.openai.com/api/docs/guides/reasoning
- Chat and Responses API references

What the docs say:
- **Limits.** Every model in scope has a 1,050,000-token context, 922K maximum input and 128,000 maximum output. All of them are supported on both Chat Completions and Responses.
- **Reasoning effort.**
  - The 5.6 models and gpt-6-sol / gpt-6-luna accept `none` / `low` / `medium` / `high` / `xhigh` / `max`, with `medium` as the default.
  - gpt-6-astra and gpt-6.1-sol do not accept `none` ("use low instead").
- **Sampling.** "When reasoning effort is not `none`, remove `temperature`, `top_p`, and `top_logprobs`." The changelog adds that Astra "does not support custom temperature or top_p values".

Decisions:
- `温度` (0–2, toggle, off by default) appears only for models that support `none`, and it requires `思考强度 = none`. Astra and 6.1 Sol have no temperature control.
- **Verbosity.** `详细程度` offers `low` / `medium` / `high`, default `medium`. It is sent as `verbosity` on Chat Completions and `text.verbosity` on Responses.
- **Max output.** `最大输出` is a toggle that starts off. Chat Completions uses `max_completion_tokens`, because `max_tokens` is deprecated there. Responses uses `max_output_tokens`. The range is 1000–128000, with a default of 32000 when switched on.
- **Chat Completions extras.** I send `stream_options.include_usage` as a silent item (https://developers.openai.com/cookbook/examples/how_to_stream_completions). Echo is off, because Chat Completions returns no reasoning field.
- **Responses extras.**
  - `思考摘要` is a toggle, on by default, that sends `reasoning.summary: "auto"`. Without it, summaries are not returned ("will not be included unless you explicitly opt in").
  - `Pro 模式` is a toggle, off by default, that sends `reasoning.mode: "pro"`.
  - Both require thinking on, i.e. effort ≠ `none`, for models that have `none`.
  - I send `store: false` and `include: ["reasoning.encrypted_content"]` as a silent item. The docs say stateless mode now includes `encrypted_content` by default, and the include value is "legacy" but still accepted. I kept it for safety.
  - Echo is on and automatic. The docs recommend preserving every output item, encrypted reasoning included, when you replay history by hand.

## Anthropic decisions
Sources:
- https://platform.claude.com/docs/en/about-claude/models/overview
- https://platform.claude.com/docs/en/build-with-claude/thinking
- https://platform.claude.com/docs/en/build-with-claude/effort
- https://platform.claude.com/docs/en/build-with-claude/preserved-thinking
- https://platform.claude.com/docs/en/build-with-claude/context-windows
- https://platform.claude.com/docs/en/about-claude/model-deprecations

Every model in scope has a 1M context (no beta header needed) and 128K maximum output. All of them are active.

Thinking, per the docs' per-model table:

| Model | Thinking | Can it be turned off? | Effort levels | Default effort |
|---|---|---|---|---|
| Fable 5.1, Opus 5.5, Fable 5 | Always adaptive | No: `disabled` gives a 400 | low–max (all five) | Opus 5.5 `medium`, the others `high` |
| Sonnet 5.5 | Adaptive by default | Not with `disabled` (400). `between_tools` turns off up-front thinking, at effort high or below only | all five | `high` |
| Opus 5 | Adaptive by default | `disabled` works at effort high or below | all five | `high` |
| Sonnet 5 | Adaptive by default | `disabled` works at any effort | all five | `high` |
| Opus 4.8, Opus 4.7 | Off unless `adaptive` is sent | Yes | all five | `high` |
| Opus 4.6, Sonnet 4.6 | Off unless `adaptive` is sent | Yes | low / medium / high / max (no `xhigh`) | `high` |

How the presets handle this:
- **Off switch.** Opus 5, Sonnet 5 and Sonnet 5.5 get a `关闭思考` toggle (off by default). It is limited by `requires` wherever an effort limit applies, so an invalid combination can't be sent. `思考显示` and adaptive thinking require that toggle to be off.
- **4.x models.** They get a `思考` toggle that is **on by default**. This is my choice; the API default is off.
- **Displayed thinking.** The API returns no thinking text by default (`display` defaults to `omitted`) on 4.7 and later. `思考显示` defaults to `summarized` so the app can show reasoning. This is my choice, not the API default.
- **Sampling.** On 4.7 and later, `temperature`, `top_p` and `top_k` return a 400 at non-default values, so those presets have no temperature control. On 4.6, temperature is incompatible with thinking, so `温度` (0–1, default 1, toggle) requires `思考 = false`.
- **max_tokens.** It is a range with no toggle (1000–128000, default 64000). The docs advise a large `max_tokens` at high effort, and suggest starting at 64k for xhigh/max on Opus 4.7, 4.8 and 5. No preset uses a `budget_tokens` mode (deprecated or rejected), so the budget-below-max_tokens rule can't be broken.

Echo is on and automatic (thinking + redacted_thinking blocks). The docs say "Recommended: across turns, pass everything back", and all these models keep prior-turn thinking. It is optional without tools.

**Key risk, preserved thinking.** Fable 5.1, Opus 5.5 and Sonnet 5.5 check that everything before a thinking block is unchanged.
- **What fails.** Editing any earlier message invalidates that block and every later one. That includes the app's in-place assistant edits.
- **Who it affects.** Accounts created on or after 2026-08-31 get a 400 by default.
- **The fix.** These three presets send `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` together with the custom header `anthropic-beta: thinking-binding-controls-2026-08-01`. The API then drops the stale blocks instead of failing.
- **Sonnet 5.5 detail.** `block_binding` must not be sent with `between_tools`, so it sits in the `思考显示` item, which is off whenever `关闭思考` is active.
- **Sonnet 5.5 account binding.** Its thinking blocks only work in the account that produced them. The app echoes only to the same provider, so this is fine.

## Could not verify / caveats
1. **CORS.**
   - Anthropic's browser support is the header the app already sends.
   - For DeepSeek and OpenAI, no official page says whether browser (CORS) calls are allowed. Please test them in the app.
2. **Temperature on GPT-5.6 with effort `none`.** The "remove temperature unless effort is none" rule comes from the GPT-6 guide. The GPT-5.6 guide doesn't mention temperature at all, so I applied the same rule to 5.6 by inference.
3. **Pro mode.**
   - The docs don't say whether pro mode works with streaming, or which effort levels it allows. Pro requests can take minutes, and the app doesn't use background mode.
   - I gated Pro on effort ≠ `none`. That is my own precaution, not a documented rule.
4. **`reasoning.summary`.** `concise` and `detailed` are "model-dependent", so the presets only send `auto`.
5. **Echoed Responses message items.** With `store:false`, the echoed message items keep their original `id`. The docs didn't say whether stateless requests accept item ids. Encrypted reasoning items are documented as the stateless path.
6. **Anthropic temperature range 0–1.** This comes from the long-standing API reference text found by search. The current reference only says temperature is deprecated for models after Opus 4.6.
7. **DeepSeek "384K".** I used 384000 as the cap; whether "384K" means 384,000 or 393,216 tokens is unclear. 384000 is safe either way.
8. **DeepSeek V4.1 Flash parameters.** The chat API page lists Flash and Pro together with one parameter set. The changelog only states the `low` / `high` / `max` effort levels for V4-Pro, so I assumed Flash takes the same.
9. **GPT-6 Astra default effort.** Its model page states no default; the GPT-6 guide says `medium`.
