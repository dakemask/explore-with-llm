# 网络转发

在「设置 → 网络转发」填写自己设置的转发密码，下载程序并运行或部署，然后填写得到的服务地址并测试连接。在各供应商设置里分别开启「使用网络转发」。聊天、旁支提问、自动命名和获取模型列表共用这个选择。旧供应商默认直连。

## Cloudflare Pages

1. 先填写供应商的接口地址及转发密码，下载 `cloudflare-relay.zip`。
2. Cloudflare 控制台 → Workers & Pages → 创建应用 → **Continue to Pages** → **Drag and drop your files**。
3. 直接拖入 ZIP，无需解压。它的根目录包含 `_worker.js`。
4. 完成部署，将 `https://项目名.pages.dev` 填回应用的转发服务器地址，测试连接。

这里使用 Pages 的拖拽部署入口。Workers 创建页面的「Upload your static files」不是这个入口。

## 本机或云服务器

安装 Node.js 22 或更新版本，下载 `relay.mjs`，在它所在目录运行：

```sh
node relay.mjs
```

默认地址是 `http://127.0.0.1:8787`，保持终端打开。浏览器可能询问本地网络访问权限。端口被占用时，可以通过 `PORT` 环境变量更改。

云服务器可以设置 `HOST=0.0.0.0`，另行配置 HTTPS 入口及后台运行。本机默认仅监听回环地址。手机上的 `127.0.0.1` 指手机自身。

## 配置更新

密码保存在当前浏览器。重复下载使用当前密码，不自动更换。修改密码后，重新下载并更新正在运行的程序；其他设备填写相同的服务地址与密码。

下载包含密码，请妥善保管。脚本允许下载时的应用来源和供应商来源；新增或修改供应商来源、变更应用域名或端口时，需要重新下载并部署。供应商 API Key 不会写入下载文件；请求发生时，它和聊天内容会经过转发服务。

## 接口与维护

`GET /health` 验证密码并返回服务标识和版本；`GET/POST /relay` 转发请求。`X-EWL-Token` 是 UTF-8 密码的 Base64 编码，`X-EWL-Target` 是目标 URL；这些头不会传给供应商。公网依赖 HTTPS 加密。转发不自动跟随重定向，不解析模型载荷，保留流式响应和上游错误。

`src/relay/runtime.js` 由两种下载共用，`src/relay/node.mjs` 负责 Node HTTP 适配。脚本的每实例频率限制是每分钟 120 次，不是分布式流量防护。`pnpm test:relay` 验证独立 Node 进程的 HTTP 错误、压缩、流式与取消；`src/relay.test.ts` 验证应用接入、接口约定与 ZIP。
